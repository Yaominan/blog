## 构建容器时，如何写 dockerfile，使用了什么参数，以及参数的作用
```bash
1、from 导入初始镜像
2、copy 从宿主机 dockerfile 同路径下拷贝文件到镜像
3、run 执行命令行的命令，主要用于定制镜像的环境和功能
4、cmd 用于指定容器运行时需要运行的命令，因为一个容器必须至少运行一个指令，容器才能存活，与 run 不同的是，run 是在构建镜像的时候运行的命令，cmd 是容器运行时需要执行的命令，同样的还有 entrypoint，注意这里的 cmd 中指定的命令的参数如果在 docker run 时也指定了，那么会被覆盖，而不会运行 cmd 后面的命令
5、env 指定环境变量，作用域是 dockerfile 内，以及作为系统环境变量，
6、arg 也是指定环境变量，不过只在构建镜像的时候用，构建好的镜像中是没有 arg 指定的变量的
7、entrypoint 指定容器启动时要执行的操作（通常是一个 entrypoint 脚本） 可以直接指定完整的命令；或者 只指定命令，参数通过 cmd 或 docker run 传入命令
8、volume 指定数据持久化存储卷
9、expose 暴露容器中的端口，方便配置映射，-p/-P 随机映射 expose 的端口
10、workdir用于指定工作目录，大概就是我们服务需要的文件放在哪个位置，docker exec 时会直接进到该目录
```
## 如何缩小镜像体积大小
```bash
1、在构建镜像的时候，减少 run 命令的操作，因为每一次 run都是基于当前镜像执行并提交成新的镜像层，所以建议多个 run 合并到一条中，使用&&链接，这样不仅能够减小镜像的体积，还能后缩减镜像的构建时间
```
## dockerfile中add 和 copy的区别是什么
```bash
1、add 拷贝压缩文件到容器中时会自动解压压缩文件，copy 不会解压缩
2、add 支持 从url 复制，copy 不支持
3、通常建议使用 copy，除非必须用到 add 的额外特性（解压、url）
```

## docker容器和虚拟机有什么区别

```bash
1、隔离性与架构
    虚拟机（VM）： 模拟了完整的物理硬件，每个虚拟机都有自己的操作系统、内核和完整的资源栈。 这种层级的虚拟化提供了非常彻底的隔离性。 
    Docker容器： 不进行硬件虚拟化，而是利用宿主机操作系统的内核。 它通过命名空间（namespace）和控制组（cgroup）等技术隔离用户空间，提供了一个独立的文件系统、进程空间和网络接口。 
2、启动速度和资源消耗
    虚拟机： 启动时需要启动整个操作系统，过程耗时较长，资源消耗较大，通常以分钟计。
    Docker容器： 启动时无需启动操作系统内核，只需加载应用程序及其依赖项，因此启动非常快速，只需几秒钟。 在同等硬件上，容器的数量也远多于虚拟机。 
3、性能和资源利用率
    虚拟机： 由于多了一层虚拟硬件和操作系统内核，性能开销相对较高，资源利用率较低。 
    Docker容器： 性能更接近原生，资源利用率更高，因为它直接利用宿主机硬件资源。 
```

### 为什么容器运行快
    因为容就是访问的宿主机的资源，就是相当于在已经开机的服务器上运行一个软件而已，它智只会加载应用需要的一些依赖项，而不是像虚拟机启动一样还要加载内核之内的

### 你知道cgroup和namespace
```bash
Namespace (命名空间)
作用： 创建隔离，让容器内的进程感觉自己在一个独立的系统中。 
实现方式： 通过封装内核的全局资源，为每个容器提供一组独立的资源实例。 
隔离的资源包括：
PID (进程ID)：: 容器内部的进程拥有自己的PID 视图，与宿主机和其他容器的进程不冲突。 
网络(Network)：: 容器有独立的网络堆栈、IP 地址和端口等。 
文件系统(Mount)：: 容器有自己独立的文件系统挂载点和根目录。 
IPC (进程间通信)：: 隔离进程间通信机制，如信号量和消息队列。 
UTS (主机名和域名)：: 容器拥有独立的主机名和域名。 
用户(User)：: 容器内用户和用户ID与宿主机不直接关联。 
Cgroup (控制组)
作用： 限制和管理容器使用的物理资源，防止一个容器耗尽宿主机的资源。 
实现方式： 通过内核提供的机制，对进程组的资源使用进行限制、统计和优先级控制。 
控制的资源包括：
CPU：: 限制容器可以使用的CPU 时间片或CPU 核心数量（如 docker run --cpus=0.5）。 
内存(Memory)：: 限制容器可以使用的内存总大小（如 docker run --memory=512m）。 
磁盘I/O (Input/Output)：: 控制容器对磁盘的读写带宽和IO 优先级。 
其他功能：
资源统计：: 统计容器的CPU 使用时间、内存使用量等，便于计费或监控。 
进程控制：: 恢复执行进程。
```

### keepalived 高可用的原理是什么，用了什么协议
```bash
Keepalived高可用原理:
VRRP协议基础: Keepalived的核心是一个集群管理服务，它利用`VRRP虚拟路由冗余协议(Virtual Router Redundancy Protocol)`协议实现服务的高可用性。 
主备模式: 在集群中，一个节点被指定为master节点，其他节点是backup节点。 master节点负责对外提供服务和处理所有流量。 
心跳机制: master节点会周期性地发送VRRP心跳包（多播）到网络中，通知backup节点它还“活着”。 
故障检测与切换:
backup节点会持续监听来自master节点的心跳包。 
如果在VRRP配置的超时时间内，backup节点没有收到心跳包，它就会认为master节点已经发生故障。 
此时，backup节点会触发一个选举过程，并通过VRRP协议成为新的master节点。 
资源接管: 新的master节点会立即接管原来master节点的虚拟IP地址（VIP）和配置的服务，从而实现服务的平滑切换，确保业务连续性。 
恢复后切换回: 当原master节点恢复正常后，它会重新启动，并在backup节点释放VIP后，重新变回backup角色的状态，恢复到原来的配置。 
```
## 节点卡顿了怎么排查，思路是什么
```bash
1、top 查看 CPU 负载以及内存占用情况，可以看到具体是哪个进程或服务占用了资源
2、free -h 查看内存是否健康
3、df 看看 磁盘容量是否健康
4、根据以上所获取的信息，判断是哪个服务导致的节点卡顿，进一步排查服务的进程，看是内存泄露或是日志文件占用大量空间等问题
5、再根据以上信息，通过 du 或者 find 命令找出大文件，删除日期久远或是没有影响的大日志文件
```

## 介绍一下容器的生命周期：
```bash
1. 容器创建
镜像拉取：Kubelet 根据容器镜像配置，开始拉取镜像。策略由 imagePullPolicy（如 Always, IfNotPresent）控制。

创建容器：容器运行时（如 containerd）创建容器环境。

2. 初始化阶段
启动后钩子：如图中所示，在容器创建后、主进程启动前，会立即执行 PostStart Hook。如果此钩子执行失败，容器将被杀死，并根据重启策略决定是否重启。

3. 主进程运行
容器的主进程（Dockerfile 中的 CMD 或 ENTRYPOINT）开始运行。

此时，探针 开始工作，它们是影响容器状态的关键因素。

4. 运行时期 - 探针决定容器状态
探针是由 Kubelet 对容器执行的定期诊断，有三种类型：

启动探针

目的：判断容器应用是否已启动。在启动探针成功之前，其他所有探针都会被禁用。

使用场景：解决启动慢的旧应用的启动问题。给它足够的时间完成启动，避免在启动过程中被存活探针杀死。

后果：如果失败，容器会被杀死并重启。

存活探针

目的：判断容器是否还在正常运行。这是容器健康状态的“生死线”。

后果：如果失败，Kubelet 会杀死容器，然后容器受 重启策略 约束而重启。

作用：重启处于“死锁”或“无响应”状态的容器，使应用恢复可用。

就绪探针

目的：判断容器是否已准备好接收外部流量。

后果：如果失败，Endpoints Controller 会将此 Pod 的 IP 从与其匹配的所有 Service 的端点列表中移除。这意味着 Service 不会再转发流量给这个 Pod。

作用：保证流量只被发送到已准备好处理请求的 Pod。例如，在容器刚启动但缓存还未加载完成时，就绪探针可以使其暂时不接收流量。

5. 容器终止
当 Pod 需要被删除时（例如手动删除、节点资源耗尽等），终止流程开始，这是一个优雅关闭的过程：

API Server 更新状态：Pod 在 API 中被标记为 “Terminating”。

PreStop Hook：Kubelet 在终止容器之前，会执行 PreStop Hook。这是一个执行自定义清理逻辑的宝贵机会（例如，通知其他服务、保存状态、优雅关闭连接）。

SIGTERM 信号：Kubelet 向容器的主进程发送 SIGTERM 信号，通知它应该开始关闭。

等待期：Kubernetes 会等待一段预定的时间，让容器优雅关闭，这个时间由 terminationGracePeriodSeconds 指定（默认 30 秒）。

强制终止：

如果在等待期内容器主进程自行退出，则终止完成。

如果等待期结束后容器仍在运行，Kubelet 会发送 SIGKILL 信号强制杀死容器。
```
